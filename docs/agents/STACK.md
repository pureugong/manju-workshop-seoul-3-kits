# Owner defaults (stack, infra, UI)

Defaults the owner has confirmed across projects. Managed by mmk-crew (copied on every `setup`). A project may override a line in its own docs; note the override in one line.

## Code
- Go: plain `net/http` is fine, but prefer chi or gin for the router (chi when it must stay net/http-compatible, e.g. Lambda via aws-lambda-go-api-proxy or a later self-hosted server). Use well-known libraries for logging, validation, retries, SDKs; don't hand-roll them.
- API middleware order: request ID, structured JSON log (slog), panic recover, timeout, CORS (own UI origin only), auth, authz (others' objects return 404), body size and per-key rate limit.
- Docs stay small. Record only the final decision, and only for choices that are costly to reverse (stack, data model, hosting, money, security): one short entry with the decision and one line of why. No option comparisons, candidate lists, "recommended plan" write-ups or long design essays in the repo; issues and PRs are the documentation: discussion, options and evidence live there, and the decision entry just links the issue/PR (full URL). Prefer updating an existing doc over adding a new one.

- One product, one repo: web app, API, infra, CLI live as folders (web/, cmd/, infra/ ...) in the same repo even when languages or hosts differ. Don't create a separate repo for a part.

## Infra
- Environments: one cloud environment, prod. Local is dev (fakes, DynamoDB Local, etc.); no dev/staging stacks for small projects. Guard risky changes with plan review, prevent_destroy and feature flags.
- AWS: the default CLI account; Terraform (OpenTofu-compatible) with S3 state; name resources `<prefix>-<env>-...`; tags project, env, owner, component, managed-by, cost-center (enforced with provider default_tags); a monthly budget alarm. No apply, DNS change, key issue or paid plan without the owner's OK.
- Internal tools live on a subdomain of pureugong.com (Route53, same account): `<tool>.pureugong.com`, API at `api.<tool>.pureugong.com`.
- Vercel (cost first):
  - One project per repo, root directory = the app folder (web/), team pureugongs, Hobby unless the owner says otherwise.
  - Production from main only; no preview deployments: commit `web/vercel.json` with `git.deploymentEnabled = {"**": false, "main": true}` (`*` does not cross `/`, so cloud/* and claim/* branches still deployed and burned the Hobby limit of 100 deployments a day) (template in mmk-crew). Every branch push otherwise creates a preview build, canceled or not.
  - Function region = the backend's region (template: hnd1 for AWS Tokyo). The default iad1 made a Tokyo API call cost 800 ms+ instead of ~55 ms (transcribe-hub, 2026-11-03).
  - Skip main commits that don't touch web/ with `ignoreCommand` in `web/vercel.json` (`git diff --quiet HEAD^ HEAD -- .`), not only in the dashboard, so the rule is reviewed in PRs.
  - Project Settings > Git must keep deployments on (API `gitProviderOptions.createDeployments = "enabled"`). When it is `disabled`, no push makes a deployment at all, main included, and nothing in the audit log says so (transcribe-hub, 2026-11-03, #92). When a main merge makes no deployment, read the Vercel commit status on that commit first (`gh api repos/<repo>/commits/<sha>/statuses`).
  - Retention by count: keep the latest 10 deployments; never shorten retention by date; the last production deploy always stays.
  - The Vercel GitHub app needs access to each new private repo (owner: GitHub Settings > Applications > Vercel > Repository access). Until then deploy with `vercel deploy --prod` from a clean main checkout.
  - Env vars only through the Vercel API/CLI with values never printed; same secrets also in SSM when the backend needs them.
  - After each production deploy: the domain returns 200 and the OG tags are present.
- Login for internal tools: Google sign-in with an allowed-email list. Multi-user features go on the roadmap unless asked.
- Secrets in SSM or local files outside the repo (`~/.config/<tool>/`, mode 600). Never in chat, repo or logs.

## UI
- Free tier first, no load-making loops in the UI: realtime is rarely needed. No fixed-interval polling. Refresh on page load, tab focus/visibility and an explicit refresh button; if a live view is truly needed, poll with backoff (e.g. 5s doubling to 60s, stop when nothing is running or the tab is hidden) or use SSE/WebSocket only when cheaper. API responses carry ETag/Last-Modified and the client sends If-None-Match so unchanged data costs a 304; set Cache-Control for static and rarely-changing data so the browser and CDN serve it.
- Every web app ships the web basics from the first release, set by what the service is:
  - favicon set (icon.svg/png, apple-touch-icon, manifest name/colors from the brand kit), a page title and description.
  - Open Graph and Twitter card tags (og:title, og:description, og:image 1200x630, og:url, og:locale ko_KR) so links preview well in KakaoTalk, Slack and chat, even for internal tools.
  - robots and sitemap by audience: public sites get robots.txt allow + sitemap.xml + canonical URLs; internal tools get robots.txt `Disallow: /`, `noindex` meta/header and no sitemap, but keep OG tags for sharing.
  - In Next.js use the Metadata API (app/icon, app/opengraph-image, app/robots.ts, app/sitemap.ts). Check with a link preview (curl the og tags) after deploy.
- Web UI is always a Next.js app (in web/ of the same repo), deployed on Vercel; self-hosted installs keep Next.js (e.g. OpenNext). Don't propose static HTML or other frameworks.
- Follow the web UI kit (Pretendard, charcoal + one orange accent, tables, Cmd+K): https://claude.ai/artifact/VVSC8E5yAd7YBkGvintPva
- Every screen supports dark and light mode (OS default, `data-theme` override, toggle saved per user).
- Check 4 screenshots per screen change: PC 1280 and phone 390, each in dark and light. 0 px horizontal overflow.
- Measure alignment, don't eyeball it: in each list/card row the left edges (badge, title, sub-text) and right edges (time, actions) must match across rows. Long titles truncate with an ellipsis instead of wrapping under a badge.
- Spacing is a method, not fixed numbers (owner, 11/4: "AI screens pick a new padding per view"; "don't fix the values, propose and let me decide"). Every project picks its own values, written once in `web/spacing.config.json` (`scale`, `gutter.phone`, `gutter.desktop`, `proximity`: `"le"` inner <= outer or `"half"` inner <= outer/2, `warn` for the softer one). Before choosing or changing them, propose: one comparison page of the real screen with 2-3 options side by side (live px labels on the gaps, phone 390 and PC 1280), a recommendation with the reason, and wait for the owner's pick. Never copy another project's numbers silently. Record the pick and date in the config file.
- Once picked, the values are enforced, not eyeballed: every margin, padding and gap uses a scale token (`--space-N`), no raw px, no Tailwind arbitrary or off-scale steps. `web/scripts/spacing-lint.mjs` (static, `--report` while adopting) and `web/e2e/spacing-check.ts` (rendered: off-scale computed values, proximity rule, side gutter, at 390/1280 dark and light) both read `spacing.config.json` and run in `make check`. Exceptions go in `spacing-lint.allow`.
- Control heights are one token (e.g. `--control-h`, about 32-36px; compact by default with tight padding and row spacing, tap area at least 32px). Buttons, inputs, selects and chips in one row share height and top/bottom edges. Enforce it with a Playwright check in `make check` on every screen at 390 and 1280 px, dark and light: fail when controls in a row differ by more than 1px in height/top/bottom, when a control is taller than the token, or when column left/right edges differ. Eyeballing is not a check.
- Buttons (kit ch. 12): one Button component with primary / secondary / ghost / danger. One primary per screen or dialog (orange fill, charcoal text). Sizes 28/36/44 px, radius 6, no pill, gradient, glow or shadow. Label = verb + object, no bare 확인/예, no emoji. Icon only when it adds meaning; icon-only buttons get aria-label and tooltip. Implement hover, active, disabled (with reason), loading (fixed width), focus-visible ring. Lint blocks gradients, raw shadows, 9999px, purple.
- Brand logos (kit ch. 13): official SVG only, in `assets/brands/<company>/` with `SOURCES.md` (URL, date, allowed colors, min size, terms). No recolor, stretch, rotate or merge; on dark use the official white version. Use only to show an integration or provider, never as decoration or endorsement. Where a logo needs permission (Cloudflare non-badge, Google), write the name as text. Footer line: names are trademarks of their owners, no affiliation or endorsement. Simple Icons for reference only.
- Vercel deploys one named branch only: `release`. Set the project's Production Branch to `release` and `web/vercel.json` `git.deploymentEnabled` to `{"**": false, "release": true}`. main merges do not deploy; the coordinator fast-forwards `release` to main when a release is wanted, batching several merges. Parallel sessions push many branches; every build, even a cancelled or failed one, counts against Hobby's 100 deploys a day.
- Ship the web app as a Docker image too (Next standalone, amd64 and arm64, non-root, health route, secrets only from env): it is the local test target and the customer install path.
- Compact is for controls, not for text. Body text 14-15px with line-height 1.6, 8-12px between paragraphs, 24-32px between sections, prose at most ~65 characters wide, table rows at least 40px. Long settings pages split into groups (side menu or tabs); long explanations start collapsed with a one-line summary (owner, 11/3: "settings text too cramped").
- Line breaks: Korean text uses `word-break: keep-all; overflow-wrap: anywhere`, headings `text-wrap: balance`, numbers stay with their unit (nbsp or nowrap), no paragraph ends with a 1-2 character last line at 390 or 1280 px (add it to the layout check).
- One content column per page: title, tabs, cards, forms and button rows share the same left and right x. Judge alignment on a gridded screenshot (vertical guides + 8px grid, e.g. screenshot-redpen grid), never by eye; send the before/after grid images. Mockup HTML runs the same layout check as the app (owner, 11/3: upload tab edges did not match the tabs).
- Logging: docs/agents/LOGGING.md. Never release to production without logs.
- Less text, more meaning (owner, 11/3): show state with shape (status dot, pill, icon, number, progress bar) instead of sentences; buttons and labels 2-4 words; at most one helper line per screen, the rest in tooltips or a collapsed detail; long rules become a small diagram (e.g. ElevenLabs -> fail -> Cloudflare). Test: a first-time user knows within 5 seconds what is connected, what is running and what to press.
- Third-party services always use their official logo (brand kit SVG or the site's own asset), never a drawn stand-in or letter badge; note the logo source in the PR.
- Settings that will grow (owner, 11/4): one topic per page with 5-8 rows, deep options one level down with a breadcrumb (Settings / AI / Auto summary), a settings search (⌘K on the settings screen) that jumps to and highlights the row, groups as a two-level side menu (Me: account and display, transcription, AI, connections, API keys / Admin: collapsed), new integrations as cards inside one Connections page, not new menu items. App sidebar keeps the 3-4 daily items; the rest goes under More. Phone: group list -> page -> sub-page. Reference: GitHub, Vercel, Linear settings, Toss.
- Never a left accent bar (owner rule, reads as AI-made): no coloured border-left, left inset box-shadow, 2-6px full-height ::before/::after, or Tailwind border-l-2+ / border-l-[colour] on cards, rows, callouts or the selected menu item (use a background tint, icon or pill instead). Also banned: rainbow/purple gradients, rows of 9999px pills, emoji as section markers. `make check` greps app and mockup CSS/TSX/HTML for these and fails; real 1px grey dividers go in an allow-list file.
- Also banned (owner, 11/4): numbered circle badges and check-circle steppers on settled screens; tinted pills or boxes holding a bold title plus a grey second line; hero-number stat rows (big number, small unit); the same status word shown twice. State is one plain line (label + switch), details in a tooltip. ai-tells check fails on a circle holding a lone digit and on a tinted pill with two text lines.
- Pages link both ways (owner rule, 11/5): a value shown read-only (a provider "on", a sync status, a default) is a link that changes it in place or opens the page that changes it (provider order, default provider, connection), and that page links back. A list row that made something (a synced recording, an import) links to the thing it made, while it runs and after it is done. Put "links both ways" in the spec of every screen issue and check it in the review table.
- Line-break check covers every text node, not just paragraphs (owner, 11/4: group title "내 설정" wrapped to two lines and passed). Single-line labels (menu items, group titles, buttons, badges, table headers) fail at 2+ lines; paragraphs fail on any line of 1-2 characters, first line included. Run at 390/768/1024/1280/1440 and with sidebars at their minimum width. Labels get nowrap + min width + ellipsis.
